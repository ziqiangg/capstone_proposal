# D-004 A supplying procedure's description is generated at build

## What is decided

Each procedure that supplies a value to an Article Record has one description per
version, generated from what runs, never written by hand: its code's digest, its pinned
library versions and, for a model, its identity, the wording of its prompt and its
settings. The renderer's version is not part of it: it is recorded with each kept rendered
copy, and with each version made from one as [[ACQ-36]] requires, and rejoins a procedure's
description only when BEACON renders a kept page again, by the owner's ruling of
2026-10-05 ("The kept copy's"). Its version is a digest of that description. The build
generates the release's procedures file from each procedure's description and commits
it with the release. The Article Record's register copies each new version's description
from that file once, keeping it as [[ACQ-14]] requires, and checks the version against
the digest; the version changes as [[ACQ-13]] requires. This rests on the owner's rulings on F1-19 (option b) and F5-01
(option a), and on the integrated plan's open item 58, ruled "Generated at build" on
2026-10-05.

## What it constrains

No description is written by hand, no version is assigned other than as the digest of
its description, and a release's procedures file is not edited after the release. The
register refuses a description whose digest does not match its version.

## What would reverse it

A procedure whose behaviour changes while its generated description does not, so that
the digest misses a change.
