# CP-004 A Re-extraction decides no fields, has one trigger and may reach erased text

## The change

Thirteen replacements and ten new rows. Replacements: [[ACQ-03]]'s requirement sentence and its rationale; [[ACQ-09]]'s requirement sentence and its rationale; [[GOV-06]]'s requirement sentence and its rationale; the Operator row of [[A-terms]] A1; the Re-extraction line of [[A-terms]] A2; [[REDERIVE_HORIZON]]'s `bounds`; [[ACQ-02]]'s rationale; [[ACQ-06]]'s rationale; [[ACQ-14]]'s requirement sentence and its rationale. Ten new rows in group ACQ, under the placeholders ACQ-n01 to ACQ-n10, each taking the next free number unless the owner assigns one; `apply` replaces each placeholder everywhere it appears in this change. Every other line of the rows and parameter named is unchanged: their frontmatter, [[ACQ-02]]'s and [[ACQ-06]]'s requirement sentences, every **Verification** line, and [[REDERIVE_HORIZON]]'s other fields and body.

```

**Replaced by:**

**2. [[ACQ-03]], the rationale, as it stands:**

```
**Rationale.** Re-derivation must stay possible when the original page is unavailable or has changed.
```

**Replaced by:**

```
**Rationale.** Re-derivation and Re-extraction must stay possible when the original page is unavailable or has changed. ```
**Rationale.** A better extraction must not move the evidence under a statement already made: each Evidence locator keeps resolving to the version it was made from (EVD-03). A re-extraction is not a Revision, since the item has not changed at its source (ACQ-06). Whether Judgements are re-derived from the new version is decided by the Trigger Register (GOV-06).

**Replaced by:**

```
**Rationale.** A better extraction must not move the evidence under a statement already made: each Evidence locator keeps resolving to the version it was made from (EVD-03). It is not a Revision, since the item has not changed at its source (ACQ-06). A result that changes nothing is confirmed instead (ACQ-n06), so each version recorded here is a change. # ACQ-n01

WHEN a release of BEACON changes the version of the procedure that extracts items' text or of a procedure that supplies values under ACQ-10 or ACQ-13, BEACON shall make, before the first Collection of each source under that release, a Re-extraction of every item of that source that is not an Erased item and whose latest raw page was collected within [[REDERIVE_HORIZON]] before the release takes effect.

**Rationale.** A better extraction procedure, or a better procedure for the fields, reaches the items held, not only those collected after it. A change of the renderer is not named: a Re-extraction reads the rendered copy kept at Collection and renders nothing, so a new renderer applies to new Collections only, and a run for it could only confirm what is held. Re-extracting a source's recent items before its first Collection under the release means that the held text a return is compared with was made by the procedures now running, so a difference is a change at the source (ACQ-06). The bound keeps a release's run in proportion as the archive grows; an older item is re-extracted when it returns (ACQ-n03), when its source's entry is corrected (ACQ-n02) or on the Operator's command (ACQ-n04). A release that changes none of these versions makes no Re-extraction under this row.

# ACQ-n02

# ACQ-n03

WHEN a Collection returns a held item that is not an Erased item and whose Article Record keeps a raw page, BEACON shall make a Re-extraction of the item before comparing the return with the item's retained version under ACQ-06, unless the versions recorded with the item's latest version (ACQ-n09), or with its latest confirmation of that version (ACQ-n06), are those of the procedures that BEACON now runs and of the Source Set entry under which the return was collected, and ACQ-07 did not erase the text of the version holding the item's latest raw page.

An item whose text was erased under ACQ-07 holds no text to compare, so its page is always extracted again for the comparison, and no row records anything of that Re-extraction (ACQ-09, ACQ-n06): the text it gives serves the comparison alone. An item whose record keeps no raw page returns under ACQ-27, and an Erased item under ACQ-22.

## Why

The owner's rulings on the [[Q-019]] forms (2026-10-04), the retention ruling and the
trim ruling of the same day, and the rulings of 2026-10-05 on group 2 are the evidence.
They do not answer [[Q-019]] or [[Q-026]]; they say what a Re-extraction decides, what
starts one, what it reads, what it records and what it never reaches, and [[ACQ-03]],
[[ACQ-09]], [[GOV-06]], [[A-terms]] and [[REDERIVE_HORIZON]] as they stand cannot say it.
[[ACQ-09]] extracts the text alone, only when a release does, records every result as a
version, and nothing keeps erased text out of it. This is the third proposal of the chain
those rulings name, after [[CP-002]] and [[CP-003]]. Each paragraph below names the item
of the integrated plan's group 2 it carries.

**Text and fields (item 1; F1-06 (b)).** The owner ruled "(b) Text and fields": "A
Re-extraction decides the four fields again from the retained material only (F1-04); the
earlier version is kept." The A2 entry Re-extraction now names the four fields with the
text, and reads from the latest raw page the record keeps; it no longer says "a later
release", since a Re-extraction is now started by other events too (item 3), and it no
longer says what is recorded, which [[ACQ-09]] and ACQ-n06 decide. [[ACQ-09]] compares the
fields as well as the text.

**Retained material only (item 2; F1-04, F1-05).** The owner ruled that re-deriving an item
"uses only its retained material and never contacts the source, including scripts or data a
kept page would load when rendered", as a reading of [[ACQ-03]]. [[ACQ-03]] binds every
Stage after Collection, and a Stage is a step an admitted item passes through, while a
Re-extraction reaches items that were not admitted; [[ACQ-03]] now names the Re-extraction
and what a kept page would load. "A kept page may be rendered again only with the network
blocked" and F1-05's "It may render the kept page with the network blocked" permit; the
integrated plan builds no re-rendering. No row obliges it: [[ACQ-03]]'s rationale says only
that a kept page may be rendered again where it can load nothing. "The renderer's version is
part of the procedure's version", and F3-14 names the renderer as a trigger; the owner's
ruling on the first assessment updates both (below, "The kept copy's"): until re-rendering
is built, the renderer is no trigger and is left out of a procedure's version, and each
version records the renderer that made the kept rendered copy it read (ACQ-n09).

**Triggers (item 3; F3-14, F2-20, F3-12, trim item 7, the ruling of 2026-10-05).** F3-14: "A
Re-extraction runs before the first Collection whenever the version of the extraction
procedure, the renderer (F1-04) or the field-deciding procedure (F1-06) changes. It covers
every article collected within REDERIVE_HORIZON." ACQ-n01 says so, without the renderer
(below, "The kept copy's"), and [[REDERIVE_HORIZON]]'s
bounds now name that reach, since a Re-extraction is not a re-derivation (A-terms). F2-20:
"When a Curator accepts a corrected version, BEACON re-extracts the items collected under the
drifted version from their retained material", and F3-14: "for that source's articles
collected under the faulty version, whatever their age, before its next Collection".
ACQ-n02 says so. F3-12: "An older held article that returns is first re-extracted from its
kept page under the current versions, recorded as a Re-extraction, and then compared", and
"A source's Collection waits until its own re-extraction has finished"; for an item whose
text was erased under [[ACQ-07]], the owner ruled "Compare, don't record". ACQ-n03 says so.
The trim accepted its item 7 as "F3-14: Curator's request deferred; the Operator may run
the runner by command", and on 2026-10-05 the owner ruled the command into this proposal: "Yes, in group
2 (Recommended)", one row granting it, indexed in A1's Operator row. ACQ-n04 grants it, and
A1 indexes it, since every capability a row grants is granted to exactly one role.

**The configuration version (item 4; F3-06 (a), with F2-20 and F3-12).** F3-06: "(a) The
version the item was collected under", "with one exception: a corrected version accepted
