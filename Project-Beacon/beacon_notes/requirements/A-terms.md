# A-terms

### A1. Actors

A role is a set of capabilities. Roles are not people: one user may hold several roles (GOV-02). Spec-authoring rule: every capability that a row grants is granted to exactly one role. The Authority column indexes what the rows grant; the behaviour itself is in the rows.

| Term | Authority |
| :---- | :---- |
| Reader | Reads what BEACON Publishes, and receives Deliveries once a Recipient. Opts in, in BEACON and then by starting the bot through the link BEACON gives, and opts out, in BEACON or through the delivery channel. Re-links their Deliveries to a chat account. Sees the Discovered items whose scope decision is OUT, with their reason, and of an item's extracted text only the passages its evidence or a search points to. Is never told of BEACON's processing, lateness or failures. |
| Curator | Product-policy authority. Changes each Governed Artefact other than the parameter register, the Methods and the Baselines; changes an Entry part of a Source Set entry other than the source's name, or a Standing, only by accepting a version of the entry. Sets the parameters the Curator owns. Gives BEACON the link to a source. Confirms or rejects the Entry parts of an Onboarding outcome, confirms that a source offers none of what an Entry part is for, and confirms that a name a source's pages give alike is the site's own. Accepts an Onboarding outcome, giving the source's name where the source's name is not established, and accepts a version of a source's Source Set entry that BEACON prepared as correcting the version in force. Enables and disables sources, sees each source's count of Failed items, and decides whether to keep, disable or remove a source whose failures reach its limit. Keeps a version of a source's Source Set entry despite what an open Drift flag on it names. Corrects a Judgement, and corrects a Published development in one action: its corrected Account and the Judgements behind it. Merges and splits developments. Restores a withdrawn development that needs no correction. Excludes a development from a Delivery. Erases an item, and lifts the erasure of an Erased item. Confirms or narrows a re-derivation, and approves Revised results. Adds a corpus and activates its Baselines. Runs the scope Method's evaluation. Receives the Curator digest. |
| Operator | Runtime authority. Runs an exceptional Cycle. Pauses and resumes scheduled Cycles. Retries failed work. Runs a Re-extraction of the items it names. Suspends and resumes delivery. Configures the delivery channel. Withdraws a Published development at once, the emergency brake, which needs no judgement of its content. Sets the parameters the Operator owns. Is alerted to a late Briefing, to each dropped item, to a source whose failures reach its limit, and to the delivery channel revoking BEACON's access, refusing a whole Delivery or refusing sends Delivery after Delivery, and receives the Operator digest. |
| Administrator | User authority. Creates users. Grants and withdraws roles, to themselves included. Deactivates users. Sets the parameters the Administrator owns. The first Administrator is created at installation. |

The **Development Team** is not a role. It is the people who build and release BEACON; while BEACON runs, they act only through the roles they hold (Administrator, Curator or Operator), and no row grants the Development Team a capability. A Method changes only with a new release of BEACON (GOV-18).

### A2. Terms

| Term | Description |
| :---- | :---- |
| **Collection and items** | |
| Item | One article, advisory or paper that a source offers. |
| Collection | BEACON fetching what one source's Source Set entry returns. |
| Completed without error | Said of a Collection, not ended under OPS-15, that read its source's listing to its end and either fetched the content of at least one listed item BEACON did not already hold or found every listed item already held, a listing with no entries included (SRC-04). A listed item BEACON no longer tries to fetch (ACQ-39) is left out. A page that shows none of what the source's Source Set entry holds as appearing on every page of the source, where it holds any, counts for this term as no fetch, and a listing, or a page of it, as read only where a page answered for it, retries included, shows what the Entry part locating the listing holds. A Collection that ends other than under OPS-15 has completed, in OPS-15's and OPS-16's sense. |
| Discovered item | An item a collection returns. |
| Held item | An item for which BEACON has retained an Article Record; BEACON "already holds" it. Whether two returns are the same item is an open question. |
| Encounter | A Collection's return of an item BEACON already holds. |
| Yield | A source yields an item when a Collection of that source returns it, BEACON did not already hold it and it is not an Erased item. Neither an Encounter nor the return of an Erased item is yield. |
| Admitted item | A discovered item whose scope\_decision is `IN` or `UNKNOWN`. |
| Revision | A later version of an item whose content has changed materially at its source or, where a Curator lifted the erasure of an item BEACON holds, the first version kept after the lift, made without comparison (ACQ-27). A Re-extraction is not a Revision. |
| Author | A person, or an organisation other than the item's Item publisher, that an item credits as its author or as having jointly released it. An item may have several Authors, or none. A name BEACON records where the item credits none is a Supplied value (ACQ-13), not an Author. |
| Item publisher | What publishes an item: the organisation the item names as publishing it or, where it names none, the item's source as its Article Record keeps it (ACQ-02). It is never an Author of that item, even where the item credits it. |
| Source publication time | The time a source states as the time it published. A source states it where the item's page declares it in its metadata, or where the source's own listing of its items gives a date for an item it publishes itself, in whatever form; a date the source gives as when the item last changed is never a publication time. A time the source states less precisely than a day, such as a month, a quarter or a year, is a Source publication time at that precision. A date BEACON reads from what the item's page prints or from its URL, or a time it works out by any other means, where the source states none, is not a Source publication time but a Supplied value (ACQ-13). Where the only time the source states cannot be read without guessing, the item has no Source publication time and BEACON supplies none: its Article Record records the time as unknown (ACQ-10). Where the source also states a time that can be read, that time is kept, and the one that cannot is recorded only as found, beside it (ACQ-10). |
| Supplied value | A title, author or publication time that BEACON records for an item where its source states none that BEACON can keep (ACQ-13). |
| Field state | How an Article Record holds each of an item's title, Item publisher, Authors and Source publication time (ACQ-10): one of three. *Kept*: the value BEACON keeps, which the source states and is the item's (for the Authors, every Author the source states that BEACON can read without guessing), with every other value the source states for it where those values disagree; a value the source states that cannot be read without guessing is held only as found, with that reason, and is never the kept value. *None stated*: that the source states none, with, for the title, a title BEACON supplies; for the Item publisher, the item's source as its Item publisher; and, for the Authors or the Source publication time, a value BEACON supplies, where it supplies one. *No kept value*: where BEACON can keep no value the source states for it for a Reason for no kept value, that reason and every value the source states for it that BEACON found, with, for the Authors or the Source publication time, that its value is unknown; for the title, a title BEACON supplies; and, for the Item publisher, the item's source recorded in place of its Item publisher, never as its Item publisher. A title and an Item publisher are never unknown. |
| Reason for no kept value | One of a closed list of circumstances concerning a field of an Article Record (ACQ-10, ACQ-11, ACQ-12): a place where the value would be found could not be read, the place being named; a value the source states cannot be read without guessing; a part of the item was not obtained, the part being named; the value cannot be derived from what BEACON retains of the item; or what BEACON found or supplied for it does not meet ACQ-02, ACQ-10, ACQ-11, ACQ-12, ACQ-13, ACQ-14, ACQ-15 or ACQ-16 or the terms they use, the part it fails being named. |
| Article Record | The retained content and metadata of one item. |
| Raw page | An item's content exactly as a Collection returns it, before any extraction: everything the Collection returns for the item that BEACON reads to extract its text or record its fields, being the item's pages, each page as rendered where BEACON renders it during the Collection, and the item's entry in the source's listing. |
| Copy | Anything BEACON makes, apart from an item's Article Record, in order to store, search or retrieve the item's extracted text, its raw page or the values kept for it under ACQ-12, whole or in part, such as a Chunk, a vector, a cache or an export; a backup holds Copies (ACQ-19, ACQ-20). A passage that BEACON's own Judgement or Account quotes as evidence is not a Copy (ACQ-26). |
| Erased item | An item that a Curator has erased under ACQ-08 and whose erasure no Curator has lifted since (ACQ-23), whether or not BEACON holds it. An item whose extracted text alone was erased under ACQ-07 is not an Erased item. |
| Extracted text | The text of an item's content as BEACON extracts it from the raw page, keeping the item's structure (its title, headings, paragraphs, lists and tables) and leaving out the page's navigation, advertising and other text that is not part of the item. |
| Re-extraction | BEACON extracting an item's text, and deciding its title, Item publisher, Authors and Source publication time, again from the latest raw page that the item's Article Record keeps. It is not a Revision (ACQ-09). |
| Chunk | A fragment of an Article Record's extracted text, within one section of the item. The unit of subject tagging and of search over retained text. |
| Source Set | The list of sources BEACON may collect from. Each entry holds what a Collection needs and whether the source is enabled. A change to an entry that alters no Entry part other than the source's name, and no Standing, makes no new version of the entry (SRC-36). |
| Entry part | One thing a version of a source's Source Set entry holds for collecting the source or recording its items' fields, such as where its listing is, how its items' addresses are told from its other pages, the ways of fetching its pages and their order, where on an item's page its body, credited authors or printed date are found, or the source's name. |
| Onboarding | BEACON sampling the pages of a source, from a link to it, to propose a version of a Source Set entry for it (SRC-22, SRC-23, SRC-31). |
| Onboarding outcome | What an Onboarding gives: who or what started it, how many items it sampled, its Entry parts' Standings, and a refusal or a proposed version of the source's Source Set entry (SRC-27). It is a refusal where BEACON observed something that makes collection impossible or not allowed. It is a refusal too where a required part is not established: the Entry part locating the listing, telling items' addresses apart, or giving the ways of fetching. A reason met under only some ways of fetching refuses nothing where another way fetches the pages. A refusal names each of its Refusal grounds. An Onboarding BEACON's own failure ended gives no outcome (SRC-34): a refusal rests on an Onboarding that finished looking. |
| Refusal ground | What a refusal names, each with its detail. Five are observed: not a public address; not reachable; collection disallowed; account needed; no listing found. A required part a Curator rejected gives a sixth, not observed: rejected by a Curator, naming the part and its recorded reason, and no other ground (SRC-24). Another listing or item address tried and not established gives no listing found, the item address's detail being that items cannot be told from other pages. Other ways of fetching not established give, per way attempted, the reason observed: account needed where refused as unauthorized or forbidden; otherwise what was observed; not reachable where it reached no page and nothing else was observed. |
| Tried | Of a required Entry part, that its Onboarding had begun to look for it: the part locating the listing, once the source's link was fetched; the part telling items' addresses apart, once a listing was found; the ways of fetching, once BEACON attempted one. A part not tried gives no Refusal ground. |
| Standing | Of each Entry part an Onboarding considered, whatever its outcome, and of each Entry part a preparing under SRC-37 re-read, exactly one of four; a part of a prepared version not re-read has the Standing it has in the version prepared from (SRC-38). *Checked*: BEACON found, on pages it did not propose the part from, that the part gives what it is for, or a Curator confirmed it (SRC-24). *Not checked*: BEACON established a value for the part, neither so found, confirmed nor rejected. *None offered*: neither of those, and the source offers none of what the part is for, as a Curator confirmed; for a re-read part SRC-25 names, as the version it was prepared from has it (SRC-38); or, for a part SRC-25 does not name, as BEACON observed on the pages an Onboarding sampled or a preparing read (SRC-24, SRC-25, SRC-37). *Not established*: any other part, such as one with no value or a rejected one (SRC-24). A part is *established* where its Standing is Checked or Not checked. |
| Drift flag | BEACON's finding that what it reads or records for a source under one version of the source's Source Set entry no longer agrees with that version's Drift reference for the thing the flag names (SRC-16, SRC-20, SRC-21). It names one Drift sign, a thing in which the two part. A Drift flag is not a Failed item. |
| Drift sign | For one version of a source's Source Set entry, a thing a Drift flag on it may name, with how it is judged: something the entry holds for reading the source's pages, by how often it finds what it is for, finds nothing or cannot be applied, or by the shape of what it finds; a field BEACON records under the entry, by how often the source states its value, its value is a Supplied value or the values the source states for it disagree; how often the source's Collections meet an address that is already an address of another item BEACON holds; how often the items the source lists whose content BEACON tries to fetch are answered with a page that shows none of what the entry holds as appearing on every page of the source, or are refused under the first way of fetching that the entry names; a listing with no entries whose answered page shows what the Entry part locating the listing holds, a listing whose first page was answered, retries included, only with pages that show nothing the Entry part locating the listing holds, or a Collection in which every item the source listed whose content BEACON tried to fetch was refused under every way of fetching that the entry names, one or more being tried, each a *whole-Collection event*, by one Collection meeting it or, once a Curator has kept the version despite a flag for it, by how often the source's Collections meet it; or something the entry holds about the source's pages, by one of its pages contradicting it or, once a Curator has kept the version despite a flag for it, by how often its pages contradict it. |
| Drift check | For a source enabled both when a Cycle started and when it closes, the version of the source's Source Set entry in force at that close and the things on it the check covers (SRC-16, SRC-20, SRC-21). It covers each thing a Drift flag on that version may name, in each way its Drift sign gives, except: a thing for which a Drift flag on that version is open; a thing by one page contradicting it or one Collection meeting it, where a Curator has kept that version despite a Drift flag for that thing (SRC-18); and a thing by one Collection meeting it, where that Collection began before a Curator last enabled the source again after disabling it (SRC-01). |
| Drift reference | For one version of a source's Source Set entry and one thing a Drift flag may name, what that version gave before it was put into effect or, where a Curator has kept that version despite a Drift flag for that thing (SRC-18), what it has given since the latest such keep. |
| Drift window | For one version of a source's Source Set entry and one thing a Drift flag may name, what BEACON judges that thing on (SRC-16, SRC-20): for a whole-Collection event, the source's Collections; for a page that shows none of what the entry holds as appearing on every page of the source, and for a refusal under the first way of fetching that the entry names, the *listed items tried*, the items the source listed whose content a Collection tried to fetch, each counted once, by the outcome of its latest try; and for any other thing, the *items recorded*, the source's items collected whose record write has completed, each counted once, by what the latest of its returns whose record write has completed gave. It holds, of those under that version, at most [[DRIFT_WINDOW]], the latest, the latest items being those first tried or collected under that version last. It leaves out an Erased item, its place given to no other; an item whose erasure a Curator has lifted (ACQ-23), until its first try since the lift or, among the items recorded, its first return since the lift that records a version, at which it is taken as first tried or collected; and anything first tried or collected, or any Collection that began, before the latest time a Curator enabled the source again after disabling it (SRC-01) or, for a thing for which a Curator has kept that version despite a Drift flag (SRC-18), before the latest such keep. |
| Open (Drift flag) | Said of a Drift flag from when BEACON raises it until the first of these: a Curator disables the source (SRC-01); a Curator accepts a version of the source's Source Set entry as correcting the flagged version (ACQ-29); a Curator keeps the flagged version despite what the flag names (SRC-18); the flagged version is no longer the version of the entry in force; or the source is removed from the Source Set. |
| Health entry | For one source and one Cycle that started with the source enabled, the Cycles whose entries the Curator digest reports (SRC-19), a source whose Collection was ended under OPS-15 included; a source has no Health entry for a Cycle that started with it disabled. It gives: the number of items the source yielded (SRC-05); whether its Collection completed without error (SRC-04) and, where it did not, why, an end under OPS-15 included; how many items the source listed whose content BEACON tried to fetch and could not, and how many of those BEACON will not try to fetch again (ACQ-39); how many of the items the Collection returned have an address, as the source gives it, that is already an address of another item BEACON holds; for a source collected from its feed or from a page listing its items, whether the Collection, unless it was the source's first or its first that began after a Curator enabled it again (SRC-01), read its listing to its end, as Completed without error reads one, and found one or more items listed there, none of them one BEACON already held; and, of its Counted versions, how many hold extracted text recorded as empty, or as extracted from another form, because the document the item offers has no text layer, how many hold it so because that document has a text layer that cannot be read (ACQ-15), how many hold a title that is a Supplied value (ACQ-13), how many are of items whose page prints, or whose URL holds, a date that differs from the Source publication time the source states, for each field how many hold values the source states for it that disagree, and, for each Reason for no kept value, how many fields they hold with no kept value for that reason (ACQ-10, ACQ-12). |
| Counted version | A version a source's Health entry for a Cycle counts: one recorded from what a Collection of the source returned, in that Cycle or an earlier one, whose record write had completed when the Cycle closed and that the Health entry of no Cycle closed before it counts, a version a Re-extraction gave being none. Each is so counted once, in the first of the source's Health entries whose Cycle closes after its record write completes; a version whose record write completes in a Cycle that started with the source disabled is counted in the source's next Health entry. |
| **Cycles** | |
| Cycle | One pass of collection and analysis over every enabled source. It is either *scheduled* (daily) or *exceptional* (started by the Operator). |
| Stage | One of the named steps an item passes through: the *field step*, deciding the title, Item publisher, Authors and Source publication time of a Discovered item that is not an Erased item from what a Collection returned for it; the *record write*, recording that return in the item's Article Record as ACQ-02, ACQ-05, ACQ-06, ACQ-22 and ACQ-27 say, including any Re-extraction that ACQ-30 makes for it and the comparison under ACQ-06; and the named analysis steps an Admitted item passes through. No other Re-extraction is part of a Stage. |
| Complete cycle | Every enabled source was attempted, the record write of every discovered item completed, and every admitted item reached the final stage. Any other cycle is **incomplete**. |
| Closed | Said of a Cycle that OPS-16 has closed. Selection, trend identification and Publication start from it. |
| Unfinished item | An item of a Cycle that is not a Failed item and is either a Discovered item whose record write has not completed or an Admitted item that has not reached the final Stage. |
| Failed item | A Discovered item for which a Stage still fails after [[STAGE_RETRY_LIMIT]] automatic retries in a Cycle. It is a Failed item of that Cycle, and may be retried in later Cycles until it is dropped. |
| Dropped item | A Failed item that BEACON has stopped processing because it failed in as many Cycles as OPS-27 allows. |
| Failure reason | What is recorded when a Stage fails: a kind, from a stated list, with free-text detail. |
| Notification | A message to a user about BEACON's own state. A Notification is not a Delivery. |
| Digest | A Notification sent once a day to every holder of one role, the *Operator digest* or the *Curator digest*, listing what the rows added to it since the previous one. |
| **Judgements and evidence** | |
| Judgement | Any determination BEACON makes rather than copies from a source. It is one of a closed list: scope decision, item\_type, subject tags, development membership, claim alignment and agreement, assessment, mapping, trend, selection, statement class, claim extraction, entity extraction. Recording an Article Record's fields (ACQ-02) is not a Judgement, including where BEACON keeps one of several values a source gives or records a Supplied value. |
| Method | The procedure that produces a judgement, including the model's identity, the prompt and the settings. Methods are versioned. A Method changes only with a new release of BEACON. |
| Method in force | The version of a Method that BEACON uses for new Judgements. |
| Decision Record | The retained record of one Judgement. Its fields are those EVD-02 lists. |
| Claim | An assertion that a source makes, in an item, about a development. |
| Aligned claims | Claims from different items that address the same fact. |
| Evidence locator | A reference that resolves to a passage in a specific version of an Article Record. |
| Confidence | The degree of certainty a Method attaches to each value a Judgement assigns. Its scale is an open question. |
| Statement class | Whether a composed statement is a source's claim, BEACON's synthesis or BEACON's judgement. |
| Speculative | Said of a statement about what may happen, or of one that has not been confirmed. It is recorded apart from the statement class. |
| Labelled example | An input with its correct outcome, carrying a provenance class. |
| Provenance class | Where a labelled example came from: `correction` or `labelling`. |
| **Developments and assessment** | |
| Development | An underlying event, incident, vulnerability, announcement, research result or campaign, however many items report it. |
| Contributing item | An Admitted item that belongs to a development. One item may contribute to several developments. |
| Development record | The page of the web interface that shows one development: its Account, its contributing items and its mappings. |
| Published development | A development whose Account BEACON has Published, in a Briefing or on its Development record. |
| Merge / Split | A Curator's correction of development membership that joins two developments reporting the same underlying event into one (*merge*), or divides one development into several (*split*). |
| Entity | A named party, actor, organisation, person, product or system an item mentions. |
| Materially new information | A contributing item that, relative to what its development already holds, (a) adds a claim no existing claim addresses, (b) changes the development's assessed significance, or (c) names an entity the development did not name. |
| Relevance | Whether an item or development concerns BEACON's subject area, which is cybersecurity, AI security included, as reported in English. It is not a priority score. |
| Significance | How large, novel or severe a development is in itself. It is assessed separately from relevance: a relevant development can have low significance, and a highly significant development can fall outside BEACON's subject area. |
| Assessment | A dated Significance value for one development, with its evidence and whether the development is Novel, under one version of the assessment criteria. |
| Current assessment | A development's latest assessment, other than a re-derived assessment that awaits a Curator's approval; until that approval, the assessment it would replace stays current (FBK-19). Its Significance is the last approved value. |
| Novel | Said of a development that BEACON created in the current Cycle, having matched it to no development it already held. |
| Criteria version | The version of the Scope Criteria, or of the assessment criteria, in force. |
| **Trends** | |
| Trend | A pattern across developments over a period. |
| Trend characterisation | Relative to the windows BEACON holds. *Emerging*: absent from every earlier window. *Recurring*: absent from the preceding window and present in an earlier one. For a trend present in the preceding window: *intensifying* if it has more constituent developments than it had there, *stable* if it has the same number, *declining* if it has fewer. |
| Active trend | A trend BEACON identified over the [[TREND_WINDOW]] ending at the cycle the Briefing is composed from. |
| **Output and delivery** | |
| Recommendation Set | The bounded, ranked selection of developments made after a scheduled Cycle. |
| Account | The single composed narrative of one development. |
| Revised result | A result that re-derivation on a trigger has changed and that a Reader can see: a re-derived Judgement such as an assessment, a mapping or a trend, or an Account recomposed because of one. |
| Withdrawn | Said of a Published development that an Operator has withdrawn (OPS-24) and that a Curator has since neither corrected nor restored (OPS-26). |
| Briefing | The Recommendation Set written up: the Account of each of its developments, in rank order, and the description of each active trend. |
| Publish / Deliver | *publish* makes an output visible in BEACON's interface; *deliver* sends it through a delivery channel to recipients. |
| Delivery channel | The external messaging service through which BEACON sends Deliveries and holding, correction and restore notices, through which a Reader completes opting in, and through which a recipient may opt out. BEACON's delivery channel is a Telegram bot that messages each recipient one to one. |
| Bot | BEACON's own account on the delivery channel, which sends every Delivery and notice and receives a chat account's start and opt-out. |
| Chat account | A person's account on the delivery channel. A Reader's *linked* chat account is the one linked to that Reader under DLV-26. |
| Opt-in | A Reader's consent to Deliveries: given in BEACON to a statement that names BEACON and says what will be delivered and on what schedule, and completed by starting the bot through the link BEACON gives for it. |
| Opt-out | A recipient's withdrawal of consent to Deliveries: in BEACON, or through the delivery channel by blocking the bot or sending it the opt-out command. |
| Delivery | One sending, on one day, of delivered entries to every current recipient through a delivery channel. |
| Delivered entry | A development as it appears in a Delivery: a condensed form of its Account (headline, why it matters, significance) and a link to its record in BEACON. |
| Recipient | A Reader who has opted in to Deliveries, with a linked chat account, and has not stopped being one (DLV-05). |
| Delivery outcome | For one recipient and one Delivery, the result of sending it: sent, if the delivery channel accepted a send, or failed, if it accepted none. A failure carries the channel's reason as reported. The reasons are an open set. |
| Correction notice | A message of its own through the delivery channel, not part of a Delivery, telling a recipient that a development in a Delivery they received has been corrected, with a link to its corrected record. |
| Holding notice | A short message of its own through the delivery channel, not part of a Delivery, telling a recipient that a development in a Delivery they received has been withdrawn while it is reviewed. |
| Restore notice | A short message of its own through the delivery channel, not part of a Delivery, telling a recipient who received a Holding notice for a development that it has been restored, unchanged. |
| Contact details | What BEACON holds to reach a user outside its interface, a linked chat account included. |
| **Governance and re-derivation** | |
| Governed Artefact | One of a listed set, each held versioned and changed only by its owner: Source Set, Scope Criteria, genre vocabulary, subject vocabulary, assessment criteria, approved mapping purposes, Trigger Register, parameter register, methods, labelled evaluation set, each Baseline. A method's owner is the release of BEACON: it changes only with a new release, never by a role. |
| Labelled evaluation set | The items, with their correct scope decisions, against which the scope Method is evaluated. |
| Trigger | An event listed in the Trigger Register. |
| Trigger Register | The versioned list of triggers, with the Judgements each one affects. |
| Forward processing | Processing a new item, a Revision, or an item that joins a development. |
| Re-derivation | Re-running a Judgement on input it has already analysed. |
| **Frameworks** | |
| Baseline | A dated, versioned capture of a control set or threat-framework corpus that BEACON maps against. |
| Active Baseline | The one Baseline of a corpus that a Curator has activated. |
| Framework item | A control of a control set, or a tactic, technique, sub-technique or mitigation of a threat framework. The granularity mapped to is an open question. |
| Mapping | A Judgement that a development bears on a framework item. |
| SSP | The control set that GovTech publishes at info.standards.tech.gov.sg: its Cybersecurity and Digital Service Standards control catalogs and, for each system type, a system-type profile. It is not a plan for any one system. |
| system-type profile | The SSP's selection of catalog controls for one system type, each at a level. The SSP site calls it a "baseline"; in BEACON, Baseline means only a captured corpus. |
| Level (SSP) | Level 0 "cardinal and mandatory", Level 1 "basic hygiene", or Level 2, optional "best practices", as the SSP defines them for a system type. |
| MITRE ATT&CK | MITRE's knowledge base of adversary tactics, techniques and mitigations, published per domain (Enterprise, ICS, Mobile). |
| MITRE ATLAS | MITRE's knowledge base of adversary tactics, techniques, mitigations and case studies against AI systems. |
| **Classification** | |
| Scope Criteria | The rules used to decide whether a discovered item concerns BEACON's subject area. They produce `IN`, `OUT` or `UNKNOWN` and are separate from the item's genre. |
| scope\_decision | `IN` / `OUT` / `UNKNOWN` for an item, with a reason and the Scope Criteria version. |
| item\_type | One or more labels, from the closed genre vocabulary, for a whole item. |
| subject\_tags | Labels, from the subject vocabulary, for one chunk. Several may apply. |
| Vocabulary gap | A record that no value of the genre vocabulary fits an Admitted item. |

### A3. Genre vocabulary

The genre vocabulary is a Governed Artefact, changed by the Curator without a code change. Its initial content is recorded in the decision note "Genre vocabulary: initial content", which links back to this section; it is not held in this annex. Whether an item concerns security at all is decided by the Scope Criteria, never by a genre.
