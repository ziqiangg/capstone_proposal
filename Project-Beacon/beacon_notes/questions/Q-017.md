# Q-017 Prompt injection from item text

## What is unknown

How must BEACON prevent the text of a collected item from steering a Method's Judgement or composed output, and how is that measured?

## Why this priority

P1: BEACON turns text that anyone can publish into advice delivered to critical-infrastructure teams, so it is itself a target, and the defence belongs in the Methods from the first one designed. The work can start under the fallback, so it is not P0 until the first Method is designed; it is not P2, because a Method built without it is expensive to rework.

## Answered when

Each Method has a stated set of allowed actions, an adversarial evaluation set of at least 100 crafted items, and a ceiling on the proportion of them that change the Method's Judgement or output, and each Method in force is measured at or below its ceiling.

## If it stays unknown

Item text is treated as data only; no Method has a tool that item text can trigger; every statement must trace to evidence ([[EVD-05]]); and the Operator's withdrawal ([[OPS-24]]) and the Curator's correction ([[FBK-16]]) are the defence after the fact.

## Evidence so far

In [[X-002]], a local model read collected page text to extract authors. Unconstrained, it named authors the page never credited (an organisation named in the body; a vendor mentioned in an advisory). Requiring it to quote the span it relied on, and accepting a name only where that span occurs verbatim in the page and holds the name, rejected those names. This bounds a model's output by its input; it is not an adversarial test of injection, and no crafted items were used.
