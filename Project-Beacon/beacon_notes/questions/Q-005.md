# Q-005 The initial Source Set

## What is unknown

Which English-language sources should the Source Set hold when BEACON starts, and what does each entry need so that a Collection can collect it ([[SRC-03]])?

## Why this priority

P1: the collection work is about to start and needs real sources, and the scraping-feasibility experiment ([[X-001]]), which answers what each entry needs, runs at this priority. The work can proceed on a trial list, so it is not P0; it is not P2, because the trial list decides which kinds of site the collection stack is built and tested against.

## Answered when

The owner approves a list in which every entry names the source, its address, how it lists its items (a feed, a listing page or an interface) and why it is included; every source publishes in English; and a trial Collection of each returns at least one item. What each entry needs so that a Collection can collect it is answered by [[X-001]].

## If it stays unknown

A trial list of English-language AI-security and cybersecurity sources, recorded with [[X-001]], serves development; it is not the Source Set that Readers rely on.

## Answer

The initial Source Set holds these ten sources. Every one publishes in English, and a trial Collection of each returned items in each of X-001's 7 full runs on 2026-09-28 (1,235 of 1,235 listed items kept). What each entry needs so that a Collection can collect it ([[SRC-03]]) is the listing and the fetch modes in order, which X-001 found collect every source, and the selector of the item's body, which X-001 used but whose extraction check did not count; they are held in `experiments/X-001/sources.json` until the Source Set has a home of its own.

| Source | Address | How it lists its items | Why it is included | What a Collection needs (from [[X-001]]) |
|---|---|---|---|---|
| METR blog | https://metr.org/blog | listing page | AI-model evaluation organisation; its predeployment evaluations are primary evidence on frontier-model risk | plain HTTP; dated listing cards; body `[class*=post-content]`; publishes every few weeks |
| Calif research | https://calif.io/research | listing page | AI-assisted vulnerability research | plain HTTP; the page declares no date, the listing shows one; body `article` |
| The Hacker News | https://thehackernews.com/ | feed | high-volume vulnerability and threat news | plain HTTP; feed dates; body `#articlebody`; the byline is not in the page metadata |
| The Straits Times, Tech | https://www.straitstimes.com/tech | listing page | Singapore's paper of record on technology and national cyber policy | plain HTTP (a headless browser meets a challenge page); undated listing; body `article`; full text is served despite paywall markup |
| CNA, Business | https://www.channelnewsasia.com/business | feed | Singapore broadcaster's business desk: regional incidents and regulation | plain HTTP; body `div.text`, less its games widget |
| OpenAI news | https://openai.com/news/ | feed | a frontier lab's own safety and security disclosures | TLS impersonation (a plain client is refused); feed dates only; body `article` |
| CISA alerts and advisories | https://www.cisa.gov/news-events/cybersecurity-advisories | feed (legacy XML) | the US national CERT: exploited vulnerabilities in critical infrastructure | TLS impersonation (a plain client is refused); its official feeds were retired in 2025, the legacy XML still serves; body `div.l-full__main` |
| Cyber Security Agency of Singapore (SingCERT) | https://www.csa.gov.sg/alerts-and-advisories/ | listing page | Singapore's national CERT, directly in scope for Singapore's critical infrastructure | plain HTTP (a headless browser is refused); dated listing; body `main`; weekly bulletins are PDFs, and one needs OCR |
| arXiv cs.CR | https://arxiv.org/list/cs.CR/recent | listing page (the 50 newest) | primary preprints on AI and systems security | plain HTTP at the 15-second crawl delay arxiv.org asks; each paper's HTML full text, else its PDF, else its abstract; its full author list and date are on the abstract page; the export API is closed to crawlers |
| HiddenLayer insights | https://www.hiddenlayer.com/innovation-hub/insights | listing page | AI-security vendor research on model and agent attacks | real Chrome, first in its chain on purpose, then plain HTTP; undated listing; body `[class*=rich-text]` |

Left out: **The Register** (security desk), whose robots.txt, updated 18 June 2026, denies AI and scraping crawlers and asks for a licence. Whether to seek one is the owner's decision, not the stack's.

What X-001 did not settle, and which this answer does not claim: extraction of metadata the page does not declare (bylines, dates, author lists) is unreliable, and is the subject of the follow-up experiment; the design cannot show blocking that starts after days of visits ([[SRC-12]], [[SRC-14]] reopen it).
