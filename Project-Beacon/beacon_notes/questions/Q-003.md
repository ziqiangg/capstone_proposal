# Q-003 How BEACON finds candidate sources

## What is unknown

By what criterion, and by what means, should BEACON find candidate sources and decide which to propose to a Curator? The owner named possible means: origins that Admitted items cite and the Source Set does not hold, web search (for example Serper), crawling (for example Firecrawl) and feed aggregation (for example FreshRSS), with open-source tools preferred. How often BEACON looks follows from the means chosen.

## Why this priority

P1: it shapes the collection work, and that work can proceed under the fallback below, so it is not P0. It is not P2, because [[SRC-11]] cannot be verified until the means fixes how often BEACON looks: as written, one search ever made satisfies it.

## Answered when

Over a trial of at least one month, the chosen criterion and means propose candidates of which a Curator adds at least 20 per cent to the Source Set, and the means states a search frequency that makes [[SRC-11]] testable.

## If it stays unknown

BEACON proposes as candidates the origins that Admitted items cite and the Source Set does not hold, each with the citing items as its evidence ([[SRC-07]]); a Curator decides each ([[SRC-08]]).

## Evidence so far

For [[X-001]], one agent using web search found 28 candidate sources across vendor research, CERTs, news and papers in a few minutes, and probing each shortlisted site classified how it lists its items (a feed, a sitemap, a paged listing, or data embedded in the page) and whether its robots.txt allows collection. robots.txt must be read to its standard's wildcard rules (RFC 9309): a common parser that ignores them would have allowed an interface a site disallows. One of eleven sources considered was excluded by its robots.txt ([[Q-005]]).
