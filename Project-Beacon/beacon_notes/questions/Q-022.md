# Q-022 A reproducible, corroborated Source publication time

## What is unknown

What makes an item's Source publication time ([[ACQ-02]]) the same whenever it is derived from the retained page, so that deriving it again on another day, as a Re-extraction does ([[ACQ-09]]), gives the value the first run gave for the same page? And how often is a publication time found in only one place wrong, given that most are? The date heuristic that decides where declared metadata and the listing give no day takes the day of the run as its latest allowed date, so its answer can move with the run day. Passing the item's collection time, which the Article Record keeps, as that latest date is one candidate; whether it is sufficient, and what corroboration a date found in one place needs, is unknown.

## Why this priority

P1: the Extractor is designed next and decides every item's date, and later Stages order items in time by it. The work can proceed with the date decided as [[X-006]] decides it, so it is not P0. It is not P2, because a date the heuristic supplies that can move with the run day would let a later derivation of the same page disagree with the first, and a wrong date found in one place passes unflagged on most items.

## Answered when

Every labelled item's publication time, derived from its retained page under clocks set to its collection day, to the day before the earliest publication time its record under the collection-day clock holds, kept or other (366 days before its collection day where that record holds none), and to a day at least 30 days after its collection (a set clock counts), is the same value on each. An item whose page was never kept is left out and counted by name; one with a record under some clocks and not others, or with a kept page and a record under none, fails. This is shown in an experiment of its own on labelled items already seen; the experiment that measures the rates below reports the same comparison on its items, and any difference there is fixed before this is answered. And, over at least 100 labelled items no design choice has seen, the rate at which the date is right is reported for each set of places the kept value was found in (two or more that agree, and one, by which place), for Supplied values by the procedure that supplied them ([[ACQ-13]]) and for fields held with no value apart, each with its count and its interval, the rate for dates found in a listing also reported by route, the listing a Collection reads apart from an archive route; and the owner rules on those rates whether a date found in one place needs corroboration, and of what kind.

## If it stays unknown

The date is decided as [[X-006]] decides it, and each value is recorded with where it was found or, if supplied, the procedure that supplied it ([[ACQ-10]], [[ACQ-13]]); beside each date the heuristic supplies the day of the run is recorded, so a later derivation that differs can be traced to it.

## Evidence so far

On [[X-006]]'s 58 kept test pages, in X-006's own status words, publication times were agreed on 2, single-source on 49 and from the fallback on 7, and right on 58 of 60 items (the two never kept). On X-005's 90 development and check items they were agreed on 9, single on 71 and fallback on 10. Agreement is not truth: on check S123 declared metadata and the heuristic agree on a date the label rejects, and nothing flags it. X-006's run and [[X-005]]'s second run, which it reproduced, were both made on 2026-10-01, so they do not show that another day gives the same dates. One development date (S210) only a model read is lost to the deterministic design. Per tier, on [[X-004]]'s held-out items, declared dates were right on 17 of 17, listing dates on 33 of 33 and the heuristic on 37 of 44.
